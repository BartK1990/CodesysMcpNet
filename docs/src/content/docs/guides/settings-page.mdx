The server's web UI at [http://127.0.0.1:5088/](http://127.0.0.1:5088/) is where you choose
**which CODESYS installation and which project** every MCP tool and REST endpoint acts on, and
where you can see and control the CODESYS session.

<Image src={settings} alt="The settings page" width="640" />

Set **Max projects** above 1 to configure further projects next to the default one: an
**Additional projects** list appears, and the session card shows one row per project. See
[Multiple projects](/CodesysMcpNet/guides/multiple-projects/).

<Image src={additional} alt="Additional projects list" width="640" />

The page follows your system's light/dark preference:

<Image src={settingsDark} alt="The settings page in dark mode" width="640" />

## Version

The badge next to the title shows the version of the running server. It is the same value
`GET /version` returns, and the one the release on GitHub is tagged with.

<Image src={badge} alt="Version badge next to the page title" width="420" />

## CODESYS session

The card at the top shows the state of the persistent CODESYS instance (see
[Persistent session](/CodesysMcpNet/guides/persistent-session/)). It refreshes on its own.
With [several projects](/CodesysMcpNet/guides/multiple-projects/) it has one row per project,
each with its own state and **Start** / **Stop** buttons.

| State | Meaning |
|---|---|
| **Stopped** | CODESYS is not running. **Start**, or the next call, launches it. |
| **Starting…** | CODESYS is launching and opening the project (30–60 s). |
| **Ready** | The project is open; calls are served in a second or two. |
| **Busy** | A script is running; the card shows which one and for how long. |
| **Stopping…** | The project is being closed. |
| **Disabled** | `KeepSessionAlive` is off: every call starts its own CODESYS. |

<Image src={ready} alt="Session card: Ready" width="640" />
<Image src={busy} alt="Session card: Busy running compile.py" width="640" />
<Image src={stopped} alt="Session card: Stopped" width="640" />

**Stop** closes the project and ends CODESYS, which releases the `.project` file so you can open
it in the CODESYS IDE. Changes that a failed request left unsaved are discarded.

### Password-protected projects

If CODESYS can't open a project without its password, the project's row says **Password
required** and asks for it. Enter it and click **Unlock**: the server opens the project with it
right away, and says so if the password was rejected.

<Image src={password} alt="Session row asking for the project password" width="640" />

The password is kept **in memory only**: it is never written to the settings files, never shown
again, and never returned by the API, so after a server restart you enter it once more. Scripts
receive it through a temporary file that is deleted as soon as the call finishes. MCP tools that
hit a password-protected project return an error telling the assistant to have you enter the
password here, so it never passes through the chat.

## CODESYS.exe path, project and profile

- **CODESYS.exe path** — the `CODESYS.exe` of the installation to use.
- **Project (.project) file path** — the project every tool and endpoint works on.
- **CODESYS profile** — the profile CODESYS is started with (`--profile`). The list is read
  from the selected installation; a saved profile that is no longer installed is shown as
  *(not found)*.

Under each path the page shows whether it exists on this machine (**Found** / **Not found on
this machine**).

**Browse…** opens a small file explorer that walks the server's own disks, filtered to `.exe`
or `.project` files. (A browser can't hand a web page the real path of a file chosen in a
native dialog, so the server lists its folders itself.)

<Image src={browser} alt="File browser dialog" width="560" />

**Save** validates both paths and writes them to `appsettings.production.json` next to the
server executable. The change takes effect within a couple of seconds; a running session
switches to the new project on the next call.

## View project structure

Shows the project tree as the server sees it: applications and folders, POUs with their type
and language, GVLs with their variable count, DUTs and ENUMs. With several projects, pick
the project in the list next to the button.

<Image src={structure} alt="Project structure tree" width="640" />
